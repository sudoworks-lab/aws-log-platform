# opensearch_serverless

Owns the rebuildable search projection: a time-series collection, Terraform-managed `logs` index and strict mapping, AWS-owned-key encryption policy, private OpenSearch Serverless-managed VPC endpoint, private search/Dashboards network policy, index data-retention policy, and separate index-manager/writer/reader data access rules.

The index-manager principal can create, update, describe, and delete only the `logs` index so Terraform can own its full lifecycle. It also needs external IAM `aoss:APIAccessAll`. The pipeline role receives AWS's documented ingestion minimum of create, update, describe, and document-write actions only for that exact index, while `management_disabled` prevents it from owning templates or mappings. It cannot read or delete indexes/documents. Reader principals can be collection-account IAM roles/users or OpenSearch Serverless SAML identities and can describe and read but cannot write or delete. Cross-account users must assume a role in the collection account. IAM readers also need external `aoss:APIAccessAll` and, when using Dashboards, `aoss:DashboardsAccessAll`; the identity platform owns SAML provider configuration and reader identity policies.

The module uses the AWS Cloud Control provider's `awscc_opensearchserverless_collection_index` resource. Its direct collection-ID reference guarantees that the collection exists before the index. Live roots pass the managed index name to OSIS, guaranteeing that the pipeline is created after the index mapping.

AWSCC index Create/Delete requires a temporary network exception for a private-only collection. `provisioning_public_access_enabled` defaults to `false`. When true, the module creates exactly one network policy named `<collection>-provision`, with `AllowFromPublic = true` and one `collection/<exact-name>` rule. It never includes a Dashboards rule and does not change the data access policy. The index explicitly depends on this optional policy node, which also keeps the exception present until index deletion during destroy.

Use `scripts/aoss-index-lifecycle.sh apply --root infra/live/<environment> -- <terraform-options>` for the true-then-false Create/Update sequence. Before destroy, use the helper's `destroy` mode so the true phase is applied before Terraform deletes the index. The outputs `provisioning_public_access_enabled` and `provisioning_public_policy_name` expose the phase and reserved policy name without sensitive data. A true value or surviving policy outside an active lifecycle operation is a steady-state violation.

The OSIS-created PrivateLink endpoint is authorized through a separate service-managed network policy named by the ingestion module. Do not point OSIS at this Terraform-managed search policy or both systems will attempt to own the policy document.
